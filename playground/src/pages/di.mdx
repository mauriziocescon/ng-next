## Dependency Injection Enhancements

<p class="subtitle">Some ergonomic tweaks to tokens and providers — mostly about reducing ceremony.</p>

`injectionToken` creates typed tokens; `providers` can depend on inputs and run in injection context.

```typescript
import { component, inject, provide, injectionToken, input, signal } from '@angular/core';

const CounterToken = injectionToken({
  debugName: 'CounterToken',
  factory: () => {
    const counter = signal(0);
    return {
      value: counter.asReadonly(),
      decrease: () => counter.update(v => v - 1),
      increase: () => counter.update(v => v + 1),
    };
  },
});

const multiToken = injectionToken.multi({
  debugName: 'multiToken',
  factory: () => Math.random(),
});

export const Counter = component({
  bindings: {
    initialValue: input<number>(),
  },
  setup: () => {
    const counter = inject(CounterToken);
    const multi = inject(multiToken); // number[]

    return @{
      <div>Value: {counter.value()}</div>
      <button on:click={() => counter.decrease()}>-</button>
      <button on:click={() => counter.increase()}>+</button>
    };
  },
  providers: ({ initialValue }) => [
    provide(CounterToken),            // shorthand — uses token's factory
    provide(multiToken),              // each call contributes one item
    provide(multiToken, () => 10),    // explicit factory override
    provide(multiToken, () => initialValue()),
  ],
});
```

<div class="annotation">
  <strong>Input-driven providers:</strong> inputs are hoisted to the component level so <code>providers</code> can depend on them before <code>setup</code> runs. Four token flavours — with factory, auto-provided, factory-less, and multi — cover the common patterns with less boilerplate.
</div>
