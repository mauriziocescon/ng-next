## Component Root & Directives

<p class="subtitle"><code>rootNode: element&lt;T&gt;()</code> declares a native-element root — directives applied to the component attach to that root at compile time.</p>

Every component has a `rootNode`: the target that directives at its call site match against. Omit `rootNode` and it defaults to `RootNode`, which leaves the template unconstrained and exposes no native element. Declare a native-element root with `element<HTMLElement>()` (or a subtype like `element<HTMLButtonElement>()`) and the template must have a single root node that is a native element, not wrapped in control flow (`@if`/`@for`/`@switch`). That declared type then decides which directives are compatible.

```typescript
import { component, input, output, computed, fragment, signal, element } from '@angular/core';
import { ripple } from '@mylib/ripple';
import { tooltip } from '@mylib/tooltip';

// -- Definition: a native-element root --
export const Button = component({
  rootNode: element<HTMLButtonElement>(),
  bindings: {
    type: input<'button' | 'submit' | 'reset'>('button'),
    disabled: input<boolean>(false),
    click: output<void>(),
    children: fragment.required<void>(),
  },
  setup: ({ type, disabled, click, children }) => @{
    <button
      type={type()}
      disabled={disabled()}
      on:click={() => click.emit()}>
      @render(children())
    </button>
  },
});

// -- Usage: directives attach to the root --
export const Consumer = component({
  setup: () => {
    const tooltipMsg = signal('Hover me');
    const valid = signal(false);

    return @{
      <Button
        type="button"
        use:ripple()
        use:tooltip(message={tooltipMsg()})
        disabled={!valid()}
        on:click={() => {}}>
          Click me
      </Button>
    };
  },
});
```

<div class="annotation" role="note">
  <strong>Directives land on the root:</strong> because <code>Button</code> declares <code>rootNode: element&lt;HTMLButtonElement&gt;()</code>, its single <code>&lt;button&gt;</code> root is where call-site directives attach. <code>use:ripple()</code> and <code>use:tooltip(...)</code> are accepted because their <code>host</code> types accept <code>HTMLButtonElement</code>. The same directive cannot appear twice on the same resolved element — a call-site <code>use:tooltip(...)</code> collides with one already written on the root inside <code>Button</code>.
</div>

<div class="annotation" role="note">
  <strong>Declaration, not a value:</strong> <code>element&lt;T&gt;()</code> is a phantom brand — nothing to call, nothing to allocate, and never passed to <code>setup</code>. It sits in a value position for the same reason <code>fragment.required&lt;void&gt;()</code> does: so <code>T</code> can be written where TypeScript will infer it, leaving <code>bindings</code>, <code>expose</code>, and the template type inferred from the same config object. <code>element&lt;RootNode&gt;()</code> is rejected; <code>RootNode</code> is not declarable.
</div>

### The declared root is a promise, not a fact

Compatibility is ordinary TypeScript assignability: a directive with host `H` fits a component when the component's declared root `R` is assignable to `H`. The check uses the declaration, never the internal tag. So a component may promise less than it renders:

```typescript
export const Button = component({
  // Promises only "some HTML element", even though its root is a <button>
  rootNode: element<HTMLElement>(),
  bindings: {
    children: fragment.required<void>(),
  },
  setup: ({ children }) => @{
    <button>@render(children())</button>
  },
});
```

That keeps the internal tag out of the public API: swapping `<button>` for `<a>` stays a private change. The cost is paid at the call site — a directive declaring `host: ref<HTMLButtonElement>()` is rejected on `<Button />`, because the component only promised `HTMLElement`.

<div class="annotation" role="note">
  <strong>Why declared and not inferred:</strong> reading the root type off the template element would always make the tightest promise. The internal tag would become public API, and changing it would break every consumer applying a tag-specific directive — reported in their code, with no declaration in the library to point at.
</div>
