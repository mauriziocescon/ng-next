## DI: Input-Driven Providers

<p class="subtitle">Inputs are hoisted — <code>providers</code> can depend on them before <code>setup</code> runs.</p>

Provider factories receive inputs as signals and run in an injection context — enabling reactive, input-driven service instances.

```typescript
import { component, linkedSignal, input, WritableSignal, provide, inject } from '@angular/core';

class CounterStore {
  private readonly counter: WritableSignal<number>;
  readonly value = this.counter.asReadonly();

  constructor(c = () => 0) {
    this.counter = linkedSignal(() => c());
  }

  decrease() { this.counter.update(v => v - 1); }
  increase() { this.counter.update(v => v + 1); }
}

export const Counter = component({
  bindings: {
    c: input.required<number>(),
  },
  setup: () => {
    const store = inject(CounterStore);

    return @{
      <h1>Counter</h1>
      <div>Value: {store.value()}</div>
      <button on:click={() => store.decrease()}>-</button>
      <button on:click={() => store.increase()}>+</button>
    };
  },
  providers: ({ c }) => [
    provide(CounterStore, () => new CounterStore(c)),
  ],
});
```

<div class="annotation">
  <strong>Inputs before setup:</strong> <code>providers</code> receives only inputs (not models or outputs). The factory <code>() =&gt; new CounterStore(c)</code> captures the input signal <code>c</code> — the store reacts to input changes via <code>linkedSignal</code>. This replaces the common pattern of injecting a service and manually feeding it inputs in <code>ngOnInit</code>.
</div>
